## 本机 Agent / 操作者步骤

1. 先读仓库 `AGENTS.md`，检查 `git status`。不要覆盖未提交修改。拉取上述分支到独立工作树，确认查看的是 PR 的最终提交。
2. 在该工作树 `weixin/` 使用 Node >=22.13 运行 `npm test`、`npm run check`。Windows 创建符号链接可能需要开发者模式/权限；若符号链接测试跳过，应记录并在具备权限的测试目录补验，不能算已验证。
3. 经本机操作者确认，使用测试 DSH 配置/账号让 `link:` 指向该工作树。不得覆盖原有生产 profile 或泄露凭据；记录实际 DSH、Node、插件版本。
4. 验证 #25：以网关开启启动，发送合成文本确认一次正常回复。关闭“启用微信网关”并保存，确认日志/网络不再启动长轮询；关闭期间的新消息不得触发新 Agent 会话或工具调用。再开启，无需重启即可恢复。另测以关闭状态启动后开启、恢复默认、账号暂停后总开关关闭/开启、关闭期间登录/恢复账号。
5. 若关闭时已有回合运行：本次行为是停止新轮询、拒绝尚未处理的队列，但允许已经进入处理的回合完成并回复。重新开启会等待该账号旧连接完成停止，再开始替代连接，可能要等旧回合完成；不表示立即取消现有 Agent 任务。
6. 验证 #24：仅在隔离测试目录临时开启 autoSendFiles，生成小的测试 PDF/ZIP，确认正常产物能收到；用无私人内容的目录外文件建立符号链接，并另造超过设置上限及空文件，确认拒绝日志出现且微信未收到。恢复原设置。不要用真实私人文件测越界。
7. 验证 #23：先运行已提供的可控 Promise 测试，不必在生产账号制造断网。真实微信中确认正常回复、重试与设置卡 outbox 展示仍正常；若测试配置已有合成失败消息，观察重试后新排队消息仍保留。
8. 在 PR 记录通过/失败、确切提交 SHA、宿主版本、复现步骤及脱敏日志。没有真机验证通过前，保持 draft 和 issues open。由本机操作者决定合并及关闭对应 issue。
